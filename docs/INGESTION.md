# Discovery and verification

Run `python3 -m ingestion.run --dry-run --max-candidates 12 --output /tmp/discovery.json` to inspect public sources without catalog writes. Live operation requires `INGESTION_API_URL` and `INTERNAL_SECRET` in the environment and an enabled ingestion API. `python3 -m ingestion.run --max-candidates 100` discovers and writes records, persists run summaries, and advances checkpoints after successful persistence.

Sources:

- **Hacker News**: [HN Search API](https://hn.algolia.com/api), using `search_by_date`, `tags=show_hn`, and timestamp filters. Each pass fully reads a bounded 24-hour window (up to five pages of 100 hits), sorts oldest first, and consumes up to its candidate quota. A timestamp/story-ID cursor preserves ties and unconsumed leads. An oversized window stops safely instead of skipping records. Initial backfill begins two days ago. This replaces the old ranked `showstories` slice. Original story URLs/timestamps are provenance, never inferred launch dates.
- **GitHub**: [official REST repository search](https://docs.github.com/en/rest/search/search#search-repositories), with separate `saas`, `productivity`, and `developer-tools` streams. No star/popularity threshold. Each stream requires a public homepage, description, and nontrivial repository size; forks, archives, tutorials, and templates are excluded. Closed UTC creation days are paged in order, with day/page/offset checkpoints. Incomplete or >1,000-result windows stop safely; public API quotas can also stop a run. GitHub indexing and topic changes can affect coverage. Repository creation is not a product launch date.
- **Submissions**: at most ten queued submissions per pass enter the same verifier. Approval allows verification; it does not bypass evidence checks or publish immediately.
- **Feeds**: RSS, Atom, and JSON adapters exist. ScrollLaunch and Product Hunt are disabled in `data/feeds.json`. Never enable a feed without a documented permission review and endpoint check.

## Fetch policy

`safe_web.py` accepts HTTPS only, disallows credentials/custom ports/literal IP identities, rejects any DNS answer set containing a non-global address, and connects to a validated IP while retaining TLS hostname verification. Public IPv4 is preferred when available so IPv4-only GitHub runners work; every DNS answer must still pass the same public-address check. Every redirect receives the same checks and destination robots review. It allows at most three content pages per domain, three redirect hops, a 10-second network timeout, two bounded network attempts for selected HTTP failures, a maximum eight-second Retry-After delay, two MiB per response, and per-domain spacing. The current verifier normally needs only one page. A source or product that requires authentication, CAPTCHA, or bypass tricks remains pending/review.

The metadata parser reads title, description, headings/body feature text, and JSON-LD without executing JavaScript. It excludes navigation/footer contents and rejects fragments over 500 characters rather than presenting a truncated mixed resource list as capability evidence. Migration 0005 replaces Otter’s concatenated resource-link excerpt with concise claims from its independently checked official feature page. Classification needs a confirmed official product identity, usable-software context, and explicit capability evidence. Descriptive launch titles may resolve to an explicit official title/site name only when it matches a label in the official domain and appears in page text. This fallback is limited to homepage/locale paths so an agency brand cannot replace a nested tool's identity. Ambiguous terms get extra checks: a founder's video-editor biography is not video-editing software, CI security scanning is not a CI service, using another cloud-storage provider is not providing file storage, and a follow-up chat question is not a sales reminder. Negative claims, integration lists, comparisons, and announced future features do not establish capabilities. Auto descriptions are original controlled prose derived from evidenced capabilities. Curated seeds have original editorial descriptions and explicit hints checked against the page.

The workflow processes at most 100 candidates per run (up from 40), at most ten submissions and ten due retries. Show HN gets 60% of remaining capacity, with reserved shares for each GitHub stream; unused capacity flows to later streams. It remains a bounded discovery sample, not a whole-internet index. If a stream produces more leads than its quota, its cursor retains the backlog for subsequent runs. Monitor checkpoint lag and increase frequency only after checking free quotas. New collector checkpoint keys (`hackernews_newest`, `github_saas`, `github_productivity`, `github_developer-tools`) start a short backfill without interpreting legacy cursors as new formats.

Candidates that temporarily fail retry with exponential day-level backoff, capped at five automatic attempts. Others go to review. Candidate source IDs and canonical URL uniqueness make reruns idempotent. Checkpoints are stored in D1, never an ephemeral runner disk. A run that fails before checkpoint completion may safely rediscover work.
